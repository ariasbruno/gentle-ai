# Native instruction modules in Antigravity CLI

The plugin keeps persona and mandatory orchestration separate from conditional procedures. Native rule discovery helps select procedures; it does not replace explicit phase loading or make ODD, applicable test-first development, or provider-owned RDD optional.

## Quick path

1. Use persona from `~/.gemini/config/plugins/gentle-ai/rules/AGENTS.md` and core obligations from `rules/gentle-ai-orchestrator.md`.
2. Before a phase or action, read its module from the core's Required Phase Loading table. Bare rule filenames resolve within the plugin's `rules/` directory.
3. For delegation, supply scoped task context and exact authorized checks; collect observed results before dependent actions or reporting completion.

## Ownership and routing

| Surface | Responsibility |
|---|---|
| `rules/AGENTS.md` | Injected persona and conversation style; not a worker's implementation policy. |
| `rules/gentle-ai-orchestrator.md` (`always_on`) | Mandatory ODD/applicable test-first obligations, phase routing, safety and rendered canonical RDD contract. |
| `rules/orchestrator-*.md` (`model_decision`) | Triggered delegation, skills, memory, tracking, writer, verification and prompt-relay procedures. |
| `rules/strict-tdd.md`, `rules/strict-tdd-verify.md` (`model_decision`) | Applicable implementation and verification guidance; legacy filenames do not imply a Strict TDD switch. |
| `agents/<role>/agent.md` | Bounded role instructions; agent bodies already use deployed paths and are not rewritten by rule rendering. |

Workers load implementation guidance before their first edit; verifiers load verification guidance before checking evidence. Applicable deterministic behavior changes need observed RED/GREEN. Passive documentation and other justified exceptions need proportionate structural or functional checks, not invented lifecycle evidence.

## Delegation without hidden context

Prefer a static role when available and suitable. The documented dynamic fallback is `define_subagent` followed by `invoke_subagent`, with `system_prompt` equivalent to the role's complete instruction body. Both routes receive the request or ODD locator, acceptance criteria, selected evidence, cwd, exact skill paths, writer edit surfaces, authorized checks/output locations, guidance locator and return shape. Children must not assume parent history or loaded rules.

Enable write tools only for authorized writers; exploration and verification remain read-only. The static generic worker disables MCP. Enable MCP in a dynamic equivalent only when needed by the task. Neither route grants worker-owned RDD approval or terminal git authority.

Foreground-until-result is a parent orchestration policy. Asynchronous execution requires documented result/status mechanisms; independent concurrency is optional. No extra hooks, flags, duplicated skills or manual rule configuration are needed.

## Safe upgrades

Deployment preflights native rule paths before writes, rejecting symlinks and nonregular files (including the core). Conditional modules use `.native-rule-ownership.json`: version 1 SHA-256 digests of the last successful generated bytes, restricted to the fixed module whitelist. Actual bytes must match current generated content or the prior digest before an upgrade; edits matching neither, malformed records and unknown paths stop deployment. This is local deployment provenance, not review/workflow authority or protection against someone rewriting both file and metadata.

Without provenance, only exact current generated modules are adopted. Completed module writes with a stale ledger self-heal on redeployment, refreshing the record after success. Interrupted writes matching neither current content nor the recorded digest, and unknown historical versions, still require explicit reconciliation; markers do not establish ownership. Legacy root/support copies are removed only when exact source bytes match, with one pinned historical exception: the 8,616-byte pre-modular HEAD core SHA-256 `f1e7b59ea21f496fe1b811a6acbf9fb7c2a8a490945c966c93f54e58d2d6e47c`. Other historical or edited copies remain conflicts. The runtime-filled regular core may redeploy; its content is provider-owned and deliberately excluded from digest ownership.

Always-on ODD distinguishes read-only investigation, explanation, review and proposals from explicitly authorized implementation. Its contractual checks do not prove model compliance. Conversation language follows the actual injected policy in `rules/AGENTS.md`, including custom personas, without an invented mode marker.

## Evidence boundary

Focused Go tests check embedded contracts, temporary-home deployment paths and rendered core obligations, including provider contract retention and per-rule size. They do not prove an actual CLI session loads a module, discovers a static role, or executes a dynamic subagent. Those require separate runtime evidence; never install or sync real user configuration just to claim it.

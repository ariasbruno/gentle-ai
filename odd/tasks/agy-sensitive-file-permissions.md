# AGY sensitive-file permissions and hook guard

Extend the Antigravity CLI permission overlay and PreToolUse hook so sensitive files receive Claude-parity protection despite the vendor schema's lack of file globs, and record the hook-contract corrections found while researching the solutions. Tracking note: this ODD feature document was created after implementation started; the evidence log preserves the actual RED/GREEN order.

## Specs

- S1: «arregla los permisos para agregar todos los que faltan» — extend the AGY deny overlay with every missing Claude-parity entry expressible in the vendor schema: broad destructive-command prefixes, enumerated .env variants, and home-absolute denies for the sensitive stores that bare workspace-relative names never covered.
- S2: «revisa los de los hooks y como solucionarlo» — close the sensitive-path gap the static schema cannot express through the PreToolUse guard (deny on the concrete tool-call path at any depth), and correct the hook documentation: Stop `decision:"continue"` is a real block per the official contract, and the L10 confinement canaries lived inside the Default preset's auto-allowed temp scope.
- S3: Vendor-verified constraints (official docs, 2026-10-15): file targets support only absolute paths, recursive directories and the global `*`; bare names resolve against workspace roots; deny read implies deny write; command targets match word-by-word prefixes with a `regex:` form; PreToolUse supports allow/auto_approve/deny/ask/force_ask/deny_unless_prior_grant; the file tools are view_file/write_to_file/replace_file_content/multi_replace_file_content (AbsolutePath/TargetFile) plus grep_search (SearchPath); the Default preset auto-allows workspace + temp dirs for file access and asks elsewhere.
- S4: Apply the new overlay to the live settings via sync and verify the merged deny list.

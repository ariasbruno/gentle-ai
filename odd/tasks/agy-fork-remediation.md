# AGY fork remediation: branch hygiene, shared-file scope, and exposure scrub

Objective: make the AGY integration publishable as an upstream PR while the fork keeps its release plumbing working; branch: `agy/ai-v4.1.1_shell-v4.2.0` (renamed from `chore/agy-integration-ai-v4.1.1-shell-v4.2.0` per S2).
Runner: `go test ./...` with focused packages per task, plus the repo guard tests; delivery: ask-on-risk / `no publication authorized`; authored-change forecast inherited from the audit (83 modified upstream files, 124 new files).

## Specs

- S1 — Fork layering: "el fork si toca archivos de upstream, PERO a la hora de hacer el pr (que esto es algo que falta mucho todavia, por eso la decision) se va a crear un nuevo branch que revierta estos cambios de lo que se toco de upstream". The PR branch is built later, not now; the fork keeps its upstream-file deltas until then. Consequence accepted: the split must stay cheap, so fork-only deltas stay isolatable.
- S2 — Branch name: "me quedo con \"agy/ai-v4.1.1_shell-v4.2.0\"". Fixed order ai→shell, `_` as the separator between the two version pairs, `agy/` prefix, never varied again.
- S3 — Agent identity: "antigravity cli no reemplaza antigravity. antigravity-cli vendria a ser el cli de antigravity (agy) lo cual es distinto a antigravity. Conviven a proposito." No unification with upstream's `model.AgentAntigravity`; the coexistence is deliberate and must be documented.
- S4 — Fix scope: "haz los fixes pensando en lo que afecta a agy y sus consecuencias en esos cambios. Si un cambio no afecta a agy no te preocupes, y si un cambio afecta a agy y tambien a otro agente, etnonces tenemos que preocuparnos por ambos." The merge/uninstall fixes cover agy and claude-code; gemini, qwen, vscode-copilot and opencode/kilocode are out of scope.
- S5 — Guard coverage documentation: "para empezar hay que arreglar la documentaacion claramente porque esto debe estar claro." Every `antigravitycli/` skip in the three shared guards gets its reason documented next to the skip, plus a decisions entry and a guard-by-guard coverage map.
- S6 — Persona assets: agy gets its own persona asset with runtime-agnostic skill-loading wording; `internal/assets/generic/persona-gentleman.md` returns to upstream bytes; the same rewording for the other generic-persona runtimes goes upstream as its own PR. Known accepted consequence: codex has no persona asset and reads the generic one, so it keeps the `<available_skills>` wording until the upstream fix lands.
- S7 — Release plumbing: "WU-5: OK" — keep the `GOBIN`/`GOPATH` hermeticity fix in its own `test(cli):` commit (upstream already uses that pattern in the same file); "WU-6: OK" — no fix needed (`9d94db0e4` replaced the TUI test with its inverse in the same commit).
- S8 — Exposure scrub: "WU-7: esta bien, arreglalo para adelante." Scrub forward in a dedicated commit, never rewrite history; add a guard that rejects absolute home paths, provider function/account ids and UUIDs in `odd/` and `docs/`.
- S9 — Deferred: "WU-3: vamos a dejar esto pendiente para lo ultimo." The hermes-precedent question and the skill-loading test wording stay pending until the end.
- S10 — Issue-first PR path: "Para hacer un pr, antes tenes que hacer un issue ... si aceptan el issue, entonce el pr sera sobre una nueva rama limpia." The issue describes the fork work; the PR branch is cut clean from `upstream/main` afterwards.

- L12: T3 done (2026-10-18). Two facts behind the scope decision. First, the merge defect was reachable: the `deny` clause was tested without the permission flag, so any list under a key with that name — top level, or nested in a non-permission object — was unioned instead of replaced, keeping values the overlay had dropped. The permission-scoped union itself is intended and stays: a generated overlay adds restrictions without erasing the user's own. Second, uninstall was asymmetric on both sides: Claude Code dropped its entire `permissions` object (the user's own rules and default mode went with it), and Antigravity CLI had no permission case at all, so the overlay this fork injects survived an uninstall permanently. Subtraction reuses `permissions.ManagedOverlay`, so the list of what gentle-ai owns has one source of truth, and `defaultMode` is removed only while it still holds the injected value: a user left in `bypassPermissions` after uninstalling would be a security regression, and the pre-install value is unknowable, so dropping the key restores the agent's own default.

# AGY Gentle statusline

Objective: ship a Gentle Shell-style custom status line for agy (Antigravity CLI), deployed by the gentle-ai plugin and registered in `settings.json` under user-ownership rules.
Branch: `chore/agy-integration-ai-v4.1.1-shell-v4.2.0` (work-unit commits on top; base `5825e03aa`). Delivery: ask-on-risk. Test runner: `go test ./internal/...` focused packages; script behavior via Go exec tests.

## Specs

S1. **Render engine in-process (reworked from the bash asset)**: the status line renders inside `gentle-ai statusline`, a subcommand of the binary the plugin already requires (the same binary the hooks invoke). It reads agy's status-line JSON payload from stdin with `encoding/json`, renders one line (plus `--title` mode, S7), and has **no external dependency** (no jq, no bash — Windows-portable). The original bash asset `statusline.sh` is removed from the bundle and pruned from upgraded installs via the legacy-files list on sync.

S2. **Segments (L18/L19 order rework)**: in order, separated by `⟡`: **bare petal + mode·model block** — idle → static `✿` (L19: no brand text, no label); active → animated petal only (frames `✿❀❁✾` by wall-clock seconds mod 4, GS tone pulse mod 8 — L19 retracts the S14 label/scanner and the S12 phase display from the line; the PreToolUse hook still records the phase file, unused by the render), then `<execution_mode> · <model.display_name>` (e.g. `planning · Gemini 3.5 Pro (High)`; without execution_mode, the model alone). **Removed by L19** (not mentioned → not wanted): location/cwd/branch, sandbox, vim mode, conversation_title right-alignment, and the `gentle ai` brand. Then: ctx = `ctx ▰▰▰▱▱▱▱▱ 43%` (8 cells; accent <80 / warning ≥80 / error ≥95; `!` ≥90, gated by `visibility.contextWarning`); cost = `$X.YZ` plain (2 decimals ≥1, 3 when <1); quota = active family only in the S16 countdown format; jobs = `⧗ N jobs` (`⧗ 1 job` singular) only when `task_count > 0`; subagents = `✦ N subagents` (`✦ 1 subagent`) only when present; engram = `🧠 <project> · <count>` (S13; count-only without project; hidden on failure/zero); rdd = `🌹 <state label>` (S15); tasklist = `⋗ done/total · T# status` (S17); git changes = `±N +A/−D` (S18: default on; hidden when clean, non-git, or failure).

S3. **Responsive and density (L18 priorities)**: survival priority — 1. petal+mode·model (never drops; truncates last); 2. tasklist; 3. rdd; 4. engram; 5. git; 6. jobs; 7. subagents; 8. ctx; 9. cost; 10. quota. On overflow by `terminal_width`, walk the segments in reverse priority (quota first): first try the segment's compact form (quota → `4h32m 38%` no bar; ctx → `ctx 43%`; subagents → `✦ 3`; jobs → `⧗ 2`; engram → `🧠 919`; tasklist → `⋗ 12/17`), then drop it; finally truncate with `…`. Density: comfortable = full forms; compact = compact forms always (gauges 6 cells); minimal = priorities 1-4 only (petal-block, tasklist, rdd, engram), compact forms. The fallback line for absent/empty/unparsable payloads is `✿` (S6 rework: petal-only, exit 0, never an error).

S4. **User-owned config** `~/.gentle-ai/statusline.json` (never written by gentle-ai, never inside the plugin dir — sync must not prune or overwrite it). Schema `{"schema":"gentle-ai.statusline/v1","density":"comfortable"|"compact"|"minimal","visibility":{"changes":false,"rdd":true,"agents":true,"usageCost":true,"modelDetails":true,"contextWarning":true}}`. Defaults when absent/malformed: density `comfortable`, all visibility flags true except `changes:false`. `visibility.modelDetails:false` hides the model segment; `usageCost:false` hides ctx+cost+quota; `agents:false` hides jobs+subagents; `rdd:false` hides the RDD segment; `contextWarning:false` hides the `!` marker; `changes:true` enables the changes segment (S5). Unknown keys ignored, malformed file → defaults (script never fails on config).

S5. **RDD segment** (default on, `visibility.rdd:false` hides): `🌹 on` / `_roses: off` → `🌹 off`, unknown → `🌹 ?`, from `gentle-ai review mode status --json --cwd <cwd>` parsing `.status.effective` (exact enum strings pinned from `internal/reviewtransaction/rdd_mode.go` RDDMode constants; worker verifies `on`/`off` literals before writing the parse). Subprocess wrapped in `timeout 0.5` only when `timeout(1)` exists (without it: no subprocess, show cached or `🌹 ?`); result cached at `~/.gentle-ai/statusline-rdd-cache.json` (`{"ts":<epoch>,"mode":"on"}`) with 30s TTL, atomic tmp+mv write; any failure → `🌹 ?` and never blocks the statusline. **Changes segment** (`visibility.changes:true`, default off): `±N +A/−D` from `git status --porcelain` count and `git diff --numstat` sums with the same timeout guard; hidden on failure or non-git.

S6. **Graceful degradation, no parser dependency (reworked)**: Go parses the payload in-process. An absent, empty, or unparsable payload prints exactly `✿ gentle ai` (brand-only line, no ANSI segments) and exits 0 — never blocks, never errors agy's renderer.

S7. **`--title` mode**: same stdin payload, prints `✿ <branch> · <model display name>` (no ANSI; agy strips escapes there anyway), exit 0. Used by the settings `title` block.

S8. **Settings registration** (global scope only; workspace scope never touches `~/.gemini/antigravity-cli/settings.json`): after `DeployPluginTreeToDir`, ensure in settings.json: `"statusLine": {"type":"command","command":"gentle-ai statusline"}` and `"title": {"type":"command","command":"gentle-ai statusline --title"}` — bare binary name (PATH-resolved by agy, Windows-portable, no HOME-baked path). Ownership rules per block: if the existing `command` is non-empty and is neither the managed subcommand nor a legacy managed script-path command → leave the whole block untouched (user-owned); if `command` is empty/absent or is ours (subcommand or legacy script path — the legacy registration is rewritten to the subcommand on upgrade) → we own `type`+`command` only. Never add or modify `enabled`, `padding`, `stack_with_default` (preserve user values verbatim when present). Injection stays a dedicated adapter-owned read-merge-write. Atomic write, preserve unknown top-level keys, byte-stable formatting for untouched files.

S9. **Uninstall** (`gentle-ai uninstall` antigravity-cli retained operations): remove the `statusLine` and `title` blocks from settings.json only when their `command` is the managed subcommand or the legacy managed script-path command; preserve user-owned blocks untouched. The legacy script file (if an older sync deployed it) is still removed with the plugin dir.

S10. **Docs**: `docs/antigravity-cli/README.md` deploy tree gains `statusline.sh`; a statusline section (new `docs/antigravity-cli/` page or subsection of `01-foundation.md`) documents segments, the config file path + schema + defaults, ownership rules, jq requirement, and that `enabled`/`padding`/`stack_with_default` are user-owned knobs (`stack_with_default:true` renders below agy's built-in line). `docs/usage.md` updated if its install-effects table names settings.json effects for antigravity-cli.

S11. **Checks**: test-first (RED→GREEN) for Go behavior: settings ownership (fill empty stub like the real `{"type":"","command":"","enabled":true}`, preserve foreign user block, re-own ours, preserve `enabled:false`/`padding`/`stack_with_default`, workspace scope no-op, atomic/byte-stable), deploy (file written 0755, overwritten on re-deploy), uninstall (removes ours, preserves user). Script behavior via Go `exec` with fixture payloads and isolated `HOME`: full line snapshot, narrow-width degradation, `--title` output, jq-missing fallback (PATH without jq), config-driven hiding. Focused packages green at each task; full affected packages at closure.

S12. **ODD phase inference via the PreToolUse hook** (mirrors Gentle Shell's tool-activity inference: reads → exploring, edits → implementing, tests → checking): `handleAntigravityPreToolUse` best-effort writes `<HOME>/.gentle-ai/statusline-phase/<safe-conversation-id>.json` = `{"phase":"…","ts":<epoch>}` (atomic tmp+mv; the write never affects the hook decision) with the phase inferred from `ToolCall.Name` (lowercased): contains read/list/search/grep/find → `exploring`; write/edit/create/move → `implementing`; run/command/bash/exec → `checking` when the args' command string matches test patterns (test, pytest, jest, vitest, `go test`, `cargo test`, `npm test`), else `implementing`; invoke_subagent/manage_subagents → `delegating`; anything else → `working`. The hook prunes sibling phase files older than 1h. The statusline uses the file when its `ts` is under 10 minutes old and `agent_state` is active; otherwise the agent_state fallback labels apply.

S13. **Engram segment `🧠 <project> · <count>`** (L15 shape): the CLI execs `engram stats` with `Dir` = payload cwd under a 500ms deadline, parses `Observations:\s+(\d+)` and `Projects:\s+(\S+)` (first token on failure), and caches `{"cwd","ts","observations","project"}` at `~/.gentle-ai/statusline-engram-cache.json` (30s TTL, atomic write; cache hit only for the same cwd). Rendering: `🧠 gentle-ai · 918`; a missing project name drops the name part. Any failure (binary missing, timeout, unparsable output) hides the segment; `visibility.engram` (default true) gates it. The GS widget's transient `✓ saved #N` is out of reach: it comes from the gentle-engram MCP channel the statusline process cannot observe (recorded in L15).

S14. **Scanner on the working label** (GS `scanWorkingText` port): while the agent is active, the phase label paints per character with a reflected-light wave — phase = unix seconds mod 15, head = phase − 3, and each character's role by distance |head − index|: 0 → bright white, 1 → yellow, 2 → bright cyan, else → dim — so the sweep advances one step per render tick together with the petal.

S15. **RDD review states** (GS label parity): beyond the switch, the segment shows the state of the repo's active review authority. Resolution reuses the stop hook's in-process path (`antigravityResolveTargetIdentity` → `ReviewTargetStatusResult.Authority.State`) under a 500ms deadline with a 30s per-root cache at `~/.gentle-ai/statusline-rdd-cache.json`. Rendering: switch off → `🌹 off`; no active authority → `🌹 on`; otherwise `🌹 <label>` with the map — unreviewed → `Not reviewed yet`; reviewing/findings_frozen/evidence_classified → `Review in progress`; fix_required/fixing/fix_validating → `Fixing findings…`; ready_final_verification/final_verifying → `Verifying…`; approved → `✓ Approved`; escalated → `Needs your decision`; invalidated → `Outdated · code changed`; anything else → `Review unavailable`. `visibility.rdd` gates the whole segment.

S16. **Quota reset-countdown format (L18)**: each active-family bucket renders `<countdown> <bar> <used%>`, the countdown derived from `reset_in_seconds`: ≥1 day → `NdMh`; ≥1 hour → `NhMm`; under an hour → `Nm`. When the bucket carries no usable countdown, fall back to the key-derived label (e.g. `weekly`). Family filtering, used% math, and multiple-bucket rendering are unchanged from S2.

S17. **Tasklist textual (L18)**: the CLI resolves the repository root from the payload cwd (the same in-process resolution pattern as the RDD path, 500ms deadline), reads `odd/tasks/*.md`, picks the most recently modified feature document, and parses its `## Tasks` lines (`- T# | specs | route | status | …`): total, `done` count, the first `in_progress` task (first `pending` when none runs), and the `blocked` count. Render: `⋗ done/total · T# in_progress` (yellow), `⋗ done/total · T# in_progress ⚠B` with blocked, `⋗ done/total` with no active task, `⋗ total/total ✓` (green) when complete. No ODD directory, empty tasks, or parse failure hides the segment; `visibility.tasklist` gates it.

S18. **Config defaults (L18/L19)**: `visibility.changes` flips to default **true** — the git subprocess runs with a 5s per-cwd cache to amortize consecutive renders; `visibility.tasklist` added, default true. Removed segments carry no flags (they are gone, not hidden). `visibility.modelDetails:false` hides the `mode · model` part (the petal remains); `usageCost:false` hides ctx+cost+quota; `agents:false` hides jobs+subagents; the rest unchanged.
